Épica 1 — Precisión del Motor de Búsqueda

4 Features · Meta: Top-1 ≥ 0.90

FT-001.1 Reranker Cross-Encoder P1 — Máxima

  • Pipeline two-stage: dense retrieval top-20 → cross-encoder → top-5 final
  • Score desglosado: scoreComponents: {semantic, crossEncoder}
  • Degradación graceful a dense-only si cross-encoder no disponible

FT-001.2 Búsqueda Semántica Pura P2 — Alta

  • expandGraph: false (o ausente) → cero contribuciones del grafo
  • Corrige ambigüedad de v2.0.9

FT-001.3 Grafo Multi-Origen P3 — Alta

  • Expansión desde top-3 (no solo mejor match como v2.0.9)
  • Estrategias: single-best, top-k (default K=3), threshold, none
  • entryPoints explícitos con precedencia absoluta

FT-001.4 /extract con OpenAI P6 — Media-Alta

  • OpenAI gpt-4o-mini reemplaza MockLlmService (regex)
  • Entidades con name, type, confidence + source en respuesta
Épica 2 — Velocidad y Latencia

3 Features · Meta: p95 ≤ 500ms

FT-002.1 Cache de Grafo P7 — Media

  • Preservación de batch fetching N+1 con top-3
  • Caché Caffeine: TTL 60s, LRU, max 1000 entradas
  • Invalidación automática ante mutaciones del grafo

FT-002.2 Cold Start Qdrant P8 — Media

  • Diagnóstico de spikes ~2s y mitigación
  • p95 ≤ 500ms en cold start, steady state y bajo escritura concurrente

FT-002.3 Cache JWT P4 — Alta

  • Cache con TTL = exp − now (típicamente 1h)
  • 100 requests: 1 validación Keycloak + 99 cache hits (≤ 5ms)
  • Resiliencia: Keycloak caído → tokens cacheados siguen funcionando

Métricas objetivo

  • p95 búsqueda: ≤ 500ms
  • p95 con grafo: ≤ 500ms
  • Cache hit JWT: ≥ 90%
  • Cache hit grafo: 2ª+ query idéntica ≥ 50% más rápida
  • Cold start: 1ª query ≤ 1s, convergencia en ≤ 10 queries

Épica 4 — API y Developer Experience

3 Features · Meta: API unificada, control granular, administración

FT-004.1 Header X-Graph-Strategy P11 — Media

  • Headers: X-Graph-Strategy (none | single | top-k | threshold), X-Graph-K, X-Graph-Threshold
  • X-Graph-Strategy: none desactiva el grafo incluso con expandGraph: true
  • Sobrescribe la estrategia del perfil por request individual

FT-004.2 Unificación search/hybrid P12 — Media

  • Un solo endpoint POST /memories/search con semanticWeight + lexicalWeight
  • 5 modos: semántico puro, léxico puro, híbrido balanceado, híbrido legacy, + grafo
  • POST /memories/hybrid mantenido funcional con headers Deprecation + Warning

FT-004.3 DELETE /admin/namespaces/{name} P13 — Media

  • Eliminación atómica: memorias + relaciones + entidades + puntos Qdrant
  • Requiere rol memory-admin. Operación todo o nada con rollback ante fallo parcial
  • Respuesta con contadores: {memories, relations, entities, qdrantPoints}
Diagramas Clave de Proceso

3 flujos que definen v2.1.0

1. Pipeline Two-Stage con Reranker (FT-001.1)

Cliente → Dense Retrieval (Qdrant top-20) → Cross-Encoder Reranker → Reordenamiento por entailment → Top-5 final Si cross-encoder no disponible: degradación graceful a dense-only (WARN en logs, crossEncoderApplied: false, sin error HTTP)

2. Expansión de Grafo Multi-Origen (FT-001.3)

Cliente → ¿entryPoints explícitos en el body? → Sí: validar (max 10, deduplicar) → BFS desde IDs del cliente → No: dense retrieval + cross-encoder → aplicar estrategia (top-k default K=3 | single-best | threshold | none) → BFS desde entryPoints automáticos → ¿Cache hit? (mismos entryPoints + depth + includeKinds) → Sí: servir desde Caffeine (~85ms) → No: BFS completo N+1 → almacenar en caché → fusionar resultados

3. Unificación de Endpoints (FT-004.2)

POST /memories/search (endpoint unificado) ├─ semanticWeight: 1.0, lexicalWeight: 0.0 → Semántico puro ├─ semanticWeight: 0.0, lexicalWeight: 1.0 → Léxico puro ├─ semanticWeight: 0.6, lexicalWeight: 0.4 → Híbrido balanceado └─ + expandGraph: true → Semántico + Grafo POST /memories/hybrid → Deprecation: true + Warning: 299 → Delega a /search (0.5 / 0.5)

Compatibilidad

v2.0.9 → v2.1.0: qué cambia y qué se mantiene

Cambios aditivos (8 reglas)

Sin impacto en consumidores existentes

  • BR-001 Pipeline two-stage (dense-only como degradación)
  • BR-003 Expansión top-3 (mejor cobertura cross-dominio)
  • BR-004 entryPoints explícitos (nueva capacidad)
  • BR-006 Cache de grafo (transparente, solo latencia)
  • BR-007 Cache JWT (transparente, solo latencia)
  • BR-010 Estrategia por perfil (nueva configurabilidad)
  • BR-011 Header X-Graph-Strategy (opcional)
  • BR-013 DELETE namespace (nuevo endpoint admin)

Cambios correctivos (5 reglas)

Mejora intencional de comportamiento

  • BR-002 Aislamiento semántico (search sin expandGraph = 100% semántico)
  • BR-005 /extract con OpenAI real (reemplaza MockLlmService)
  • BR-008 Worker inactivo resuelto (deuda operativa)
  • BR-009 1 colección Qdrant (elimina overhead duplicado)
  • BR-012 Unificación endpoints (hybrid deprecado, funcional)

Garantías de no ruptura

  • Stack, modelo de datos, roles RBAC: inalterados
  • Parámetros existentes: mismos nombres, tipos y defaults
  • Códigos de error v2.0.9: sin cambios
  • Suite multi-dominio: 100% equivalente o mejor
