¿Qué se despliega?

R1-MVP: Backend de Memoria Operativa

Plataforma backend API-first para capturar, estructurar, validar, recuperar y auditar conocimiento operativo reutilizable por agentes.

  • 8 módulos funcionales — Gestión de memorias, API operativa, búsqueda semántica, persistencia, gobierno, depuración, acceso y contrato API.
  • 13 endpoints REST — Altas, consultas, búsqueda semántica, aprobación, archivado, trazabilidad y gestión de casos.
  • Stack tecnológico: Quarkus Java 21, PostgreSQL, Git/GitHub, Qdrant, Keycloak OIDC, Kubernetes.
Propuesta de valor del MVP

Repositorio único de memoria operativa con trazabilidad Git, búsqueda semántica y gobierno por criticidad, sin UI dedicada.

Alcance R1-MVP

17 historias de usuario Must sobre 8 épicas. Cobertura funcional completa de creación, consulta, búsqueda, gobierno y depuración de memorias.

Fuera de alcance

Sin UI dedicada, sin Neo4j/Redis/Kafka en MVP, sin multi-repositorio. R2 diferido con 15 criterios adicionales.

Limitaciones conocidas (no bloqueantes)

Adapters en memoria para tests automatizados; entorno integrado OIDC+PostgreSQL real requiere smoke test; pruebas de rendimiento diferidas a estabilización.

Estrategia de reversión

Plan de Rollback

La estrategia de rollback se basa en revertir a la versión anterior (o estado limpio) de cada componente con scripts predefinidos. Tiempo máximo de rollback: 30 minutos.

Componente Estrategia Procedimiento Tiempo est.
Backend Quarkus Kubernetes rollback kubectl rollout undo deployment/abax-memory 2 min
PostgreSQL Migración DOWN Ejecutar scripts de rollback de schema (pre-generados) 5 min
Qdrant Recrear colección vacía Eliminar colección y recrear desde snapshot pre-deploy 5 min
Keycloak Restaurar realm Importar realm desde exportación pre-deploy 5 min
Secrets / Config Revertir ConfigMaps Aplicar versión anterior de ConfigMaps y Secrets 3 min
Criterios de activación de rollback
  • Falla en smoke tests post-deploy (cualquier endpoint crítico con error 5xx).
  • Error en migración de base de datos que no puede resolverse en caliente.
  • Health check del backend en estado DOWN por más de 5 minutos.
  • Incidencia de severidad Blocker detectada en los primeros 30 minutos.
  • Pérdida de conectividad con GitHub API que impida operaciones core.
Decisión de rollback

El Project Manager es la autoridad de decisión de rollback, con consulta obligatoria al Tech Lead y DevOps Lead. Si no hay consenso en 5 minutos, el PM tiene voto dirimente.
