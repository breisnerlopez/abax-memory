Kickoff 02
PMOA / Abax-Memory Objetivo y contexto
Objetivo

Poner en marcha un MVP auditable y reutilizable

El objetivo es habilitar un proceso confiable para transformar casos y conocimiento operativo en memorias reutilizables, con validación por criticidad, trazabilidad Git y consumo por API.

  • Reducir pérdida de conocimiento operativo y respuestas inconsistentes.
  • Permitir recuperación semántica y filtrada de memorias útiles.
  • Asegurar trazabilidad de origen, cambios, aprobación y depuración.
Contexto aprobado

Fase 0 ya cerró con visión, épicas y backlog priorizado aprobados. El proyecto inicia con enfoque backend, API-first y sin UI dedicada en el MVP.

Criterios de éxito iniciales

≥95% de memorias con metadatos completos, 100% de memorias críticas con validación humana y ≥30% de mejora esperada en localización de conocimiento versus línea base.

Resumen ejecutivo 03
PMOA / Abax-Memory Alcance aprobado MVP
Incluye

Capacidades comprometidas en R1-MVP

  • Alta de memorias desde caso y manual en Markdown + frontmatter.
  • Versionado y auditoría en Git/GitHub.
  • API REST para crear, consultar, listar, aprobar y archivar.
  • Metadatos en PostgreSQL y búsqueda semántica con Qdrant.
  • Clasificación, criticidad, estados y validación humana por PR.
Fuera de alcance en MVP
  • UI dedicada para usuarios finales.
  • Visibilidad granular por memoria o permisos finos.
  • Automatización total de aprobación humana.
  • Multi-repositorio y portabilidad Git avanzada.
Gobernanza de alcance

Cualquier solicitud adicional se tratará por control formal de cambios; no se aprueban ampliaciones sin evaluación de impacto en tiempo, costo, calidad y riesgo.

Matriz de riesgos

Riesgos abiertos desde el arranque

ID Riesgo Probabilidad Impacto Mitigación
R-01 Demora en definición final de política de criticidad y aprobación humana. Media Alto Workshop temprano con PO/BA; congelar reglas mínimas antes de diseño técnico.
