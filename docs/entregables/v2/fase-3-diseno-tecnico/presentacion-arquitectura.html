Arquitectura

Modular Monolith (Modulith)

2 artefactos de despliegue compartiendo un solo código base:

  • memory-api: API REST v2 — operaciones síncronas (CRUD, búsqueda, revisión)
  • memory-worker: Procesamiento asíncrono — indexación Qdrant, reconciliación

¿Por qué no microservicios?

  • Velocidad de desarrollo (66 historias Must en un ciclo ágil)
  • Simplicidad operativa (1 código base, 2 artefactos)
  • Transaccionalidad ACID en PostgreSQL sin sagas complejas
  • Preparado para extracción gradual si la escala lo requiere (ADR-005)

Integración

Qdrant — Consistencia Eventual Controlada

Modelo: PostgreSQL es la fuente canónica de verdad transaccional. Qdrant es un índice derivado regenerable.

  1. Transacción ACID en PostgreSQL: crear/actualizar memoria + insertar processing_jobs en misma transacción
  2. Indexación asíncrona: memory-worker procesa jobs, genera embeddings vía OpenAI, upsert en Qdrant
  3. Idempotencia: jobs idempotentes por (memory_id, job_type). Retry con backoff exponencial (máx 3 intentos)
  4. Degradación controlada: Qdrant no disponible → API sigue funcionando para CRUD. Búsqueda semántica retorna 503 DATABASE_UNAVAILABLE

Colección Qdrant abax_memories_v2: vector size 3072 · Cosine distance · HNSW index (m=16) · Payload filters: tenant_id, kind, status, topics, entities, importance, confidence, sensitivity.

Regenerable: ante corrupción o cambio de motor de embeddings, se regenera completamente desde PostgreSQL.

Seguridad

3 Pilares: OIDC · RBAC 5×13 · Multi-Tenant

1. OIDC con Keycloak 26

  • Authorization Code + PKCE (frontend SPA)
  • JWT validado en cada request: firma RS256, expiración, issuer, audience
  • Claims custom: tenantId, realm_access.roles

2. RBAC — 5 Roles × 13 Operaciones

RolAlcance
api-consumerBuscar y consultar memorias active
memory-operatorCrear, actualizar, relacionar memorias propias
memory-reviewerAprobar/rechazar memorias en revisión
memory-adminGobernanza total, cross-tenant, config
memory-auditorConsultar auditoría, estadísticas, trazabilidad

3. Multi-Tenant Isolation — Discriminator Column

  • Columna discriminadora: tenant_id en todas las tablas
  • Filtro automático: TenantIdFilter (interceptor JAX-RS global)
  • Cross-tenant 404: si tenant A consulta recurso de tenant B → 404 NOT_FOUND
  • Admin cross-tenant: solo memory-admin con registro de auditoría obligatorio

Referencia

Glosario

  • ADR: Architecture Decision Record — documento que registra una decisión arquitectónica, su contexto, alternativas evaluadas y consecuencias.
  • Qdrant: Base de datos vectorial open-source para almacenar embeddings y ejecutar búsqueda semántica por similitud de coseno.
  • OIDC: OpenID Connect — protocolo de autenticación sobre OAuth 2.0 que permite verificar identidad y obtener claims desde Keycloak.
  • RBAC: Role-Based Access Control — control de acceso basado en 5 roles: api-consumer, memory-operator, memory-reviewer, memory-admin, memory-auditor.
  • Modulith: Monolito modular — patrón que implementa bounded contexts como módulos dentro de un solo deployable, preparado para evolución futura a microservicios.
  • PKCE: Proof Key for Code Exchange — extensión de OAuth 2.0 que protege SPAs contra ataques de interceptación de código de autorización.
  • JWT: JSON Web Token — token de acceso firmado que transporta claims del usuario (sub, tenantId, roles, exp).
