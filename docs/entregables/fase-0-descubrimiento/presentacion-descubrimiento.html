Visión del producto

PMOA busca convertir conocimiento operativo disperso en memoria reutilizable y auditable

La plataforma se concibe como un backend API-first para capturar, clasificar, validar, recuperar, persistir y depurar memorias operativas con trazabilidad completa basada en Git/GitHub.

  • Reduce pérdida de conocimiento y baja reutilización.
  • Mejora consistencia de respuesta entre agentes y operadores.
  • Hace verificable origen, cambios, validación y depuración.
Propuesta MVP

Repositorio único de memorias, sin UI dedicada, con creación manual o desde casos, búsqueda semántica, validación por criticidad y exposición por API REST.

Fuera de alcance inicial

UI dedicada, multi-repositorio, visibilidad fina por memoria, automatización total de aprobación crítica y orquestación multiagente completa.

Épicas y features · MVP I

EP-001 Gestión de casos operativos

Alta de casos, metadatos operativos, soporte sin memoria previa y cierre con resultado.

EP-002 Modelo canónico de memoria

Plantilla base, tipos de origen, metadatos obligatorios y reglas de nomenclatura/ubicación.

EP-003 Captura y generación de memoria

Creación manual, creación desde caso, borrador editable y versión inicial controlada.

EP-004 Clasificación y extracción estructurada

Clasificación por dominio/tipo, extracción mínima, etiquetado e identificación de criticidad.

EP-005 Recuperación y reutilización

Búsqueda semántica, filtros estructurados, ranking de coincidencias y reutilización en caso activo.

EP-006 Relacionamiento y grafo de dominios

Relaciones entre memorias, dominios dinámicos, vínculo caso-memoria y navegación contextual.

Lectura ejecutiva

El primer bloque funcional cubre la captura del conocimiento, su estructura estándar y la capacidad de recuperarlo con contexto operativo.

Valor para negocio

Estas épicas atacan el problema principal: convertir experiencia operativa dispersa en conocimiento reutilizable con mínimo esfuerzo adicional.

Épicas y features · MVP II

EP-007 Validación y aprobación

Validación estructural, validación funcional básica, PR manual para críticas y estados de validación.

EP-008 Persistencia Git y versionado

Repositorio único, commits de cambios, flujo Git completo e integración inicial con GitHub.

EP-009 Atención operativa multiagente

Registro de agentes, trazabilidad de aportes, consolidación de resolución y asociación con memorias.

EP-010 Depuración y ciclo de vida

Archivado, detección de duplicadas, fusión y eliminación controlada.

EP-011 Auditoría y trazabilidad

Historial de cambios, trazabilidad extremo a extremo, evidencias de validación y registro de depuración.

EP-012 Plataforma API-first

APIs de casos, memorias, búsqueda/recuperación y auditoría/depuración.

Núcleo operativo

Este bloque asegura control, auditabilidad y consumo por integración, condición necesaria para una salida inicial sin interfaz dedicada.

Punto de control

La revisión humana de memorias críticas y la operación basada en Git son dependencias funcionales explícitas del MVP.

PMOA - Plataforma de Memoria Operativa para Agentes Fase 0 · Descubrimiento · 2026-05-01
Alcance propuesto

Qué entra en el MVP

  • Creación de memorias desde caso y manual.
  • Markdown + frontmatter como formato canónico.
  • Persistencia versionada en Git/GitHub.
  • Metadatos, búsqueda semántica y filtros estructurados.
  • Validación humana por PR para memorias críticas.
  • Estados de ciclo de vida, archivado y trazabilidad por API.
Diferido

Qué queda para después

  • UI dedicada para usuarios finales.
  • Portabilidad multi-proveedor Git y multi-repositorio.
  • Visibilidad granular por memoria o segmento.
  • Fusión avanzada, enriquecimiento avanzado y reglas críticas más profundas.
  • Navegación visual de grafo y gobierno segmentado.
